% --- Section 1: Introduction ---
\section{Introduction}

\subsection{Purpose}
The purpose of this document is to define the Software Requirements Specification (SRS) for the \textbf{Traffic Safety Mobile Application (Version 1.0)}. This document outlines the functional and non-functional requirements of the system, acting as a comprehensive guide for developers, project managers, and stakeholders. It covers the entire scope of the system, including accident reporting, emergency dispatching, and user management.

\subsection{Document Conventions}
This document follows professional SRS standards. Priority levels (High, Medium, Low) are assigned to system features to guide development. Requirements are identified by unique tags (e.g., \texttt{REQ-1}).

\subsection{Intended Audience and Reading Suggestions}
This document is intended for:
\begin{itemize}
    \item \textbf{Developers \& QA Testers:} To understand technical implementations and write test cases.
    \item \textbf{Project Managers:} To track feature development and define milestones.
    \item \textbf{Stakeholders:} To ensure alignment with road safety objectives.
\end{itemize}
\textit{Suggestion:} Readers should start with Section 2 for context before proceeding to the detailed features in Section 4.

\subsection{Product Scope}
The Traffic Safety Mobile Application is a multi-platform mobile system that allows drivers to report incidents, police officers to manage traffic events, and emergency services to respond to alerts in real-time. The primary goals are reducing emergency response times and providing real-time traffic safety information to citizens.

% --- Section 2: Overall Description ---
\section{Overall Description}

\subsection{Product Perspective}
The product is a new, self-contained mobile ecosystem designed to bridge the gap between citizens (drivers) and official authorities (Police, Emergency Services). It integrates GPS tracking, multimedia reporting, and real-time notification services.

\subsection{Product Functions}
Based on the system's architecture, the application provides the following major functions:
\begin{itemize}
    \item \textbf{Citizen (Driver) Portal:} Reporting accidents/hazards, SOS alerts, and live navigation.
    \item \textbf{Police Officer Portal:} Incident classification, dispatching services, and issuing e-fines.
    \item \textbf{Emergency Services Portal:} Receiving dispatch alerts, navigating to scenes, and updating status.
    \item \textbf{Administrative Portal:} User management, system configuration, and analytics reporting.
\end{itemize}

\subsection{User Classes and Characteristics}
\begin{itemize}
    \item \textbf{Driver:} General public users; requires an intuitive and highly accessible UI.
    \item \textbf{Police Officer:} Field personnel; requires rapid access to incident data and dispatch tools.
    \item \textbf{Emergency Services:} First responders; requires precise location data and navigation.
    \item \textbf{Administrator:} Technical staff; manages system integrity and data analytics.
\end{itemize}

\subsection{Operating Environment}
\begin{itemize}
    \item \textbf{Platform:} Android 10+ and iOS 14+.
    \item \textbf{Backend:} Cloud-hosted infrastructure (Node.js/Firebase).
    \item \textbf{External Interfaces:} Google Maps API for navigation.
\end{itemize}

\subsection{Design and Implementation Constraints}
\begin{itemize}
    \item \textbf{Connectivity:} Must handle intermittent data connection in remote areas.
    \item \textbf{Security:} Data encryption for sensitive user information and police logs.
    \item \textbf{Privacy:} Adherence to GDPR and local data protection regulations.
\end{itemize}

\subsection{User Documentation}
Integrated in-app tutorials for drivers and an online help center for emergency personnel and administrators.

% --- Section 3: External Interface Requirements ---
\section{External Interface Requirements}

\subsection{User Interfaces}
\begin{itemize}
    \item \textbf{Citizen UI:} Simplified dashboard with "One-Tap SOS" and "Report" buttons.
    \item \textbf{Authority UI:} Map-centric view showing active incidents and unit locations.
    \item \textbf{Admin UI:} Web-based dashboard for data management and reporting.
\end{itemize}

\subsection{Software \& Hardware Interfaces}
\begin{itemize}
    \item \textbf{Hardware:} Access to GPS for location and Camera for multimedia attachments.
    \item \textbf{Software Interfaces:} Firebase Auth for authentication and Cloud Firestore for real-time data.
    \item \textbf{External API:} Google Maps API for rendering routes and maps.
\end{itemize}

\subsection{Communications Interfaces}
\begin{itemize}
    \item \textbf{HTTPS:} Port 443 for all secure data transmission.
    \item \textbf{FCM:} Firebase Cloud Messaging for real-time dispatch and safety notifications.
\end{itemize}

% --- Section 4: System Features ---
\section{System Features}

\subsection{Accident Reporting}
\textbf{Priority: High.} Allows drivers to submit detailed reports of road accidents.
\begin{itemize}[label=--]
    \item \texttt{REQ-1}: System MUST capture GPS coordinates automatically during report submission.
    \item \texttt{REQ-2}: System SHOULD allow optional photo/video attachments.
\end{itemize}

\subsection{Emergency Dispatch}
\textbf{Priority: High.} Enables Police Officers to send alerts to Emergency Units.
\begin{itemize}[label=--]
    \item \texttt{REQ-3}: System MUST provide real-time notification to the selected emergency unit.
\end{itemize}

\subsection{Traffic Alerts \& Navigation}
\textbf{Priority: Medium.} Drivers can view real-time hazards and navigate safely.
\begin{itemize}[label=--]
    \item \texttt{REQ-4}: System SHOULD display live traffic alerts on the navigation map.
\end{itemize}

% --- Section 5: Other Requirements & Rules ---
\section{Other Requirements}

\subsection{Performance \& Security}
\begin{itemize}
    \item SOS alerts must be transmitted within 2 seconds of the user's action.
    \item Maps must load within 3 seconds under 4G connectivity.
    \item All user data must be encrypted at rest and in transit.
\end{itemize}

\subsection{Software Quality \& Business Rules}
\begin{itemize}
    \item \textbf{Availability:} 99.9\% uptime target for the dispatch system.
    \item \texttt{BR-1}: Only verified Police Officers can issue E-Fines.
    \item \texttt{BR-2}: Emergency units only see incidents assigned to them.
\end{itemize}
